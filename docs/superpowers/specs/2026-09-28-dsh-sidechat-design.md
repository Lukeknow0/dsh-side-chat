# DSH 独立侧聊插件：产品与技术设计

状态：用户已确认的设计基线（**不是已实现插件**）<br>
目标宿主：DSH Web 与 DSH Desktop；首个 Desktop 验收基线为 `/Applications/DeepSeek Harness.app` 0.1.7-rc.2。<br>
交付：独立公开 GitHub 仓库、带版本号且可安装的包；首版不发布 npm。<br>
实现原则：从零编写源码；`dsh-sidenote` 仅作为用户可见行为参考，不复制其源码、图片或样式。

## 1. 用户目标与边界

新插件只承担**完整侧边聊天工作线**及相关划选注释、问答回流。不实现文件浏览器、编辑器、Git、任务面板或网页预览；这些继续由 `dsh-better-sidebar` 提供。其原有 `sidechat` 页面可在设置中关闭，数据不删除、不强行迁移。新插件应不依赖 `betterSidebar` 服务才能启动；两者共存是发布门槛，不是文档上的宣称。

侧聊不是摘要问答弹窗：它从主会话当前状态分叉为可持续的子会话，工具、模型、权限、审批、附件和多轮历史构成独立工作线；结论是否回主线由用户控制。新建时继承主会话当时的上下文、模型和权限，之后侧聊切换模型/权限**不改变主会话**。分别提供复制主会话 ID 和侧聊 ID 的按钮；复制 ID 不等于授予跨会话读取权限。

每个主会话可以保存多条侧聊历史，但右栏同一时间只显示一条；新建时将当前侧聊收进历史列表，可重开。切走主会话隐藏该主会话的侧聊，切回恢复；隐藏不取消已运行任务，也不持续渲染或轮询非当前面板。重启后恢复关联关系、草稿和可恢复的历史，不重复创建子会话。

## 2. 架构与模块边界

| 模块 | 单一职责 | 与其他模块的接口 |
|---|---|---|
| Host 会话服务 | 通过 DSH 公开的会话/Agent 能力创建、恢复、取消子会话；以 Typert `TypertRemoteService` / `@Remote` 暴露经过认证的 Host 操作，并限制每个 child 的父子归属 | 接受父会话身份、子会话身份和操作；不允许客户端伪造父子关系；优先采用有界分页 Remote 调用而非无限 SSE |
| Host 附件适配 | 使用宿主认可的附件/上传服务，验证媒体类型、大小、文件回执和子会话归属 | 只向该子会话的 prompt 提交已准入内容 |
| Client 右栏适配 | 注册独立命名空间的原生 Sidebar Tab、面板槽和入口；保证卸载/HMR 清理 | 不注册 `dsh-better-sidebar:*` ID，不覆盖文件页 |
| Client 会话状态 | 当前主会话到子会话列表/当前子会话的映射、草稿、重开与恢复 | 持久化身份而非整份转录；Host 是会话内容权威 |
| Client 侧聊面板 | 转录、模型/权限切换、工具与审批/提问、附件进度、发送/停止 | 使用上述 Host 和 DSH 公开能力，不直接改会话日志 |
| Client 注释与回流 | 主会话助手消息的划选注释，以及选定侧聊完整问答的待发送卡片 | 主输入框发送时序列化一次；失败不清空对象 |

客户端使用原生 `sidebarRightTabs` / 对应 slot 等公开接入点；Host 端原则上通过 DSH Typert Remote Gateway 暴露业务操作，避免把插件 API 依赖于仅面向浏览器的 `webServer` 自定义路由。具体接口签名须在目标 DSH 版本下核实，不能假设 Web 与 Desktop 转发行为一致。事件优先用有界 Remote 分页/轮询；只有证实目标 Desktop 支持时才采用流式事件。可选地只为 `better-sidebar` 关闭旧 `sidechat` 页面；如验证确需修补其注册生命周期，只做独立、可回滚、带测试的最小补丁，聊天逻辑仍保留在新插件中。不修改签名 Desktop 应用或关闭鉴权/CORS/Origin 校验来“修好”路由。

## 3. 功能行为

### 3.1 会话与输入

- 主会话已存在且可分叉时才能新建侧聊；继承快照应有明确的切割边界，不把主会话未领取的输入误投侧聊。
- 模型与权限选择属于子会话；独立保存并在重开后正确显示。审批、提问在侧聊面板处理；工具结果只在所属子会话展示。
- 面板自己提供选择文件、粘贴截图等入口；图片是图片附件，PDF/Word 等普通文件通过 DSH 实际提供的上传服务获取回执并绑定**子会话**。不得先上传到主会话再复用回执，也不得用仅含路径的文字冒充附件。
- 上传状态含等待、进行、失败、重试、移除；尚未就绪不得发送。切换侧聊不把草稿/附件串给其他子会话。遵循宿主文件格式和大小上限，不私自扩大。
- 根据实际宿主接口决定拖放、进度和粘贴兼容层；目标至少覆盖电脑选文件和粘贴截图。无法满足的交互需显式提示，不静默吞文件。

### 3.2 注释与回流

- 注释仅从**主会话助手回复**的划选发起，可编辑/删除；记录来源消息身份、引文和定位信息。刷新后无法可信定位时标为待确认，不贴到错误文本。
- 注释作为待发送对象保留，不污染草稿；主会话下一条消息由用户主动发送时一次性带入。发送失败保留对象，发送成功才消费，避免丢失或重复发送。
- 侧聊回流只选一轮完整且已结算的真实用户问题及助手回答；不把推理、工具结果或上下文注入当成问答，也不默默截断。主输入框上方显示来源、问答预览、移除入口；**点击回流不自动发送、不弹二次确认**，下一条主消息发送时带入。
- 主会话切换时待发送对象按主会话隔离；恶意或意外混入的侧聊文本应作为引用数据呈现，而不是提升为高优先级指令。

## 4. 首要风险：Desktop 共存与传输

已有对照：`dsh-sidenote@0.4.4` 与 `dsh-better-sidebar@0.21.1` 同装在当前 Desktop 后，用户看到旧侧聊和文件/网址预览失效；卸载 `sidenote` 后恢复。控制台曾出现 `dsh-better-sidebar:files` 重复注册、`POST dsh-app://app/sidebar/api/...` 405、`ws:///app/sidebar/ws/...` 无主机名，以及部分 403。**这些是故障证据，不足以推断新插件必然重现，也不能证明单一根因。**上游 Discussion [#6934](https://github.com/deepseek-ai/deepseek-harness/discussions/6934) 描述开发版 Desktop 的 `webServer` 自定义路由未被 `dsh-app://` 转发、同源校验 403；官方 [HTTP Server 契约](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/web-server.md) 明确 `webServer` 面向浏览器，Desktop fetch 走 IPC bridge。另一个针对打包版 Desktop `0.1.7-rc.2` 的 [Discussion #7868](https://github.com/deepseek-ai/deepseek-harness/discussions/7868) 报告 `/plugins/events` 无限 SSE 在 `dsh-app://` 下报 `net::ERR_FAILED`，虽然直连 loopback HTTP 正常。两条是上游报告而非本机当前 build 的复现证据，但和本机历史 405/403 症状相关，必须纳入阶段 0。设计因此优先测试 DSH [Typert Remote Gateway](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/api-gateway.md) 的有限请求和有界分页，不自建 `webServer` 路由或无限 SSE；若加载/状态仍依赖损坏的事件通道，停止并记录宿主阻塞。

**阶段 0 是阻断门槛，而非可跳过冒烟：**先在独立 Web 测试 profile 中只注册一个空的、独立 ID 的侧聊 Tab 和一个 authenticated Typert Remote unary health call，同时保留 `better-sidebar` 文件页并关闭其旧 `sidechat`。不为 probe 添加自定义 `webServer` 路由、无限 SSE 或 WebSocket；先确认初始插件图/Host bootstrap/当前主会话身份是否能在目标 Desktop 正确加载。Desktop profile 由 Electron 管理，**不能假设可直接用 CLI 建立第二个 Desktop profile**；先验证是否可用独立 `DSH_HOME` 做 Desktop 测试。若做不到，备份当前 profile 的 package、lock、patch 与安装日志，在用户可接受的维护窗口短暂安装测试包，冷启动验证后立即回滚或保留验证通过的版本。对 Web 和 Desktop 各做冷启动（不是仅 HMR），验证：

1. 原生右栏指南中**新插件入口**恰好一项；打开/关闭/切换后没有重复注册；卸载恢复原状。
2. `better-sidebar` 的文件页、文件预览与网页打开仍可工作。
3. 最小 Host `Typert Remote` unary ping 在 Desktop 真正可达且鉴权正确；主会话身份和初始插件图加载正确。业务事件仅用有限分页/轮询，不依赖无限 SSE。记录错误码/响应体与浏览器 Console，不以“UI 能显示”替代。
4. Desktop 完整退出重启后仍通过 1–3；Web 也通过。

若 405、403、无效 WS 或重复注册仍出现，先缩小到 Desktop 转发、插件挂载生命周期或本插件构造 URL 的具体边界，写最小复现与回归测试。必要时修补 `better-sidebar` 只限兼容层；若根因在当前 Desktop 且插件侧无法安全修正，**停止功能实现并报告宿主阻塞**，不以关鉴权或改签名 App 绕过。原始稳定 profile 的 package/lock/patch 做备份，验证失败原样回滚。

## 5. 可交给便宜模型的阶段任务与门槛

每一阶段单独给模型完整输入（本设计、相关 API 契约、允许改动的目录和对应测试），**不得用一个超长提示让它一次写完**。每阶段由更强的审查者核对测试结果和边界，再放行下一阶段。

| 阶段 | 产出 | 必须通过的验收 |
|---|---|---|
| 0. 共存与宿主协议 | 最小包、受保护 Host 探针、原生空 Tab、冷启动脚本 | 第 4 节四条门槛；没有用户数据损失或弱化鉴权 |
| 1. 会话核心 | 创建/恢复/重开、父子关联、独立模型/权限、ID 复制 | 分叉快照正确、切换主会话不串线、重启不产生孤儿、运行任务不中断 |
| 2. 完整侧聊 UI | 转录、多轮发送、工具/审批/提问、运行状态、性能约束 | 独立工作线操作闭环；历史可重开；非当前面板不高频轮询 |
| 3. 附件 | 图片、截图粘贴、PDF/Word 等宿主支持文件、上传状态/回执 | 无跨会话回执复用；纯附件消息和混合消息；失败可恢复，不误发 |
| 4. 注释与回流 | 主会话划选注释、问答配对、待发送卡片与发送事务 | 刷新保留、定位失败显式提示、发送失败不清空、不自动发送、不重复注入 |
| 5. 包装与发布 | README、许可、安装/卸载/回滚说明、版本包、GitHub Release 草案 | Web 与 Desktop 实测、全量回归、公开包安装与删除都不损坏历史 |

自动测试至少覆盖：权限与父子会话越权、重复注册及 disposer、冷恢复、文件类型/大小/上传失败、两会话附件隔离、完整轮识别（用户消息可能先于 `turn/start`）、注释锚点失配、回流成功/失败幂等、消息与截图同发、切换/重启性能。静态单测不足以代替真实 Desktop E2E。测试数据使用隔离会话，不复用用户真实聊天。

## 6. 非目标与开放验证项

- 首版不迁移旧 `better-sidebar` 侧聊历史，不替换其文件页；旧数据保留，必要时可临时重新打开旧页查看。
- 首版不做多个侧聊面板同时在屏渲染；允许一主会话有多条可重开的历史。
- 不承诺任意 PDF/Word 均能被所有模型解析；上传成功、Host 准入和模型实际理解是三层验收，必要时显示不支持信息。
- 原生文件上传 API、模型/权限变更 API、审批与事件回放在目标版本的签名需通过源码/类型及真机实验确认；不能根据旧版或另一插件的实现直接推断。
- 项目命名、公开仓库地址、许可证文本、GitHub Release 版本号在建立新仓库阶段确定；不把未定值伪装成已决定。

## 7. 执行纪律

在每阶段改动前写可失败的行为测试；先看到预期失败，再实现最小代码、跑局部和相关回归。每批相关改动集中完成后统一校对和验证，不每改一处便单独打断用户。每个阶段保留可审查的提交与回滚点；不直接覆盖正在运行的 Desktop 插件。正式切换必须基于第 4 节门槛和阶段 5 的 E2E 证据。
